# Read-only GitHub deploy-key bootstrap

Status: **`SOURCE_READY_SERVER_UNVERIFIED`**

This procedure creates one repository-scoped ED25519 key on the intended n8n host and registers only its public key with `appolon1908-hue/N8N`. It does not clone, pull, restart, import, activate, or deploy anything.

## Security boundary

- The private key is generated by `ssh-keygen` on the target host.
- Do not paste, print, upload, or copy the private key.
- GitHub receives only the single-line public key with `read_only=true`.
- The key is scoped to `appolon1908-hue/N8N`; the script rejects another repository.
- SSH uses a dedicated host alias, private key, configuration fragment, and known-hosts file.
- `IdentitiesOnly yes`, `IdentityAgent none`, strict host-key checking, password-authentication denial, and agent-forwarding denial are enforced.
- The scanned GitHub ED25519 host key must match GitHub's published fingerprint before it is trusted.
- An existing matching GitHub deploy key is accepted only when API readback proves it is enabled and read-only.
- The script validates `ssh -T` repository identity and `git ls-remote` without changing a checkout.
- A sanitized local evidence JSON is written with mode `0600`; it contains no private or public key material.

## Prerequisites

Run as the Unix account that will perform future read-only Git operations. Required commands are `bash`, `gh`, `git`, `jq`, and OpenSSH client tools.

Creating or reading repository deploy keys through GitHub's API requires suitable repository Administration permission. Prefer a one-time `GH_TOKEN` supplied only to the process. Do not store a broad personal token on the server.

The source repository is public, but the API credential is needed to register and verify the repository deploy key. Remove the one-time token from the environment immediately after the command.

## Run an immutable source revision

After this change is protected-merged, resolve the current protected `main` SHA once, display it, and use that exact SHA for the script download:

```bash
set -Eeuo pipefail

read -rsp 'One-time GitHub token: ' GH_TOKEN
printf '\n'
export GH_TOKEN
SOURCE_SHA="$(gh api repos/appolon1908-hue/N8N/commits/main --jq '.sha')"
printf 'SOURCE_SHA=%s\n' "$SOURCE_SHA"

TMP_SCRIPT="$(mktemp)"
cleanup() {
  rm -f "$TMP_SCRIPT"
  unset GH_TOKEN
}
trap cleanup EXIT

gh api \
  -H 'Accept: application/vnd.github.raw+json' \
  "repos/appolon1908-hue/N8N/contents/ops/bootstrap_github_deploy_key.sh?ref=${SOURCE_SHA}" \
  >"$TMP_SCRIPT"

chmod 0700 "$TMP_SCRIPT"
bash -n "$TMP_SCRIPT"
REPOSITORY='appolon1908-hue/N8N' bash "$TMP_SCRIPT"
```

Do not commit the token, put it in shell history, or paste it into an issue. A non-persistent secret-injection mechanism is preferable to interactive entry when one is available.

Successful output includes:

```text

DEPLOY_KEY_MODE=READ_ONLY
SSH_AUTH_IDENTITY=appolon1908-hue/N8N
PRIVATE_KEY_MODE=0600
PUBLIC_KEY_MODE=0644
IDENTITIES_ONLY=yes
STRICT_HOST_KEY_CHECKING=yes
PRIVATE_KEY_EXPORTED=NO
LIVE_APPLICATION_DEPLOYMENT=NO
WORKFLOW_IMPORT=NO
SERVICE_RESTART=NO
LIVE_CAPABILITY_ACTIVATION=NO
```

The remote URL is:

```text
git@github-n8n-readonly:appolon1908-hue/N8N.git
```

Repeat the read-only Git check without touching a checkout:

```bash
git ls-remote git@github-n8n-readonly:appolon1908-hue/N8N.git HEAD
```

The script also requires `ssh -T` to authenticate as `appolon1908-hue/N8N`.

## Revoke

1. Remove the matching key from **Repository settings → Deploy keys**.
2. Remove the dedicated private/public key files, SSH fragment, known-hosts file, and evidence file from the target host.
3. Confirm the repository-specific alias can no longer authenticate.
4. Do not change an application checkout or restart n8n as part of revocation unless a separate approved operation requires it.
